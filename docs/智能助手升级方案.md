# 智能助手升级方案（需求与设计基线）

> 状态：**v1.0 已决策，待评审后进入 P0**（2026-11-04）
> 代码基准：`main @ 03a2f14`（文中行号以此为准，后续漂移按函数名检索）
> 关联文档：`README.md` §Web 页面、`docs/architecture.md`、`docs/REPORT.md`、`docs/adr/0007`、`docs/adr/0010`
> 本文回答三件事：**做成什么样、为什么这么定、怎么验收**。详细接口与表结构在 P0 立项后单独出设计稿。

---

## 0. 一页结论

- **定位**：智能助手不是独立聊天页，是值班台的**第二块屏**——平时问、急时叫、处置时一起看。
- **三个目标**：问得清（答案能直接干活）、叫得应（突发必达且有人接手）、合得上（一条预警上的人、任务、回执在同一条线上）。
- **六条已定决策**：常驻抽屉（D1）、席位声明身份（D2）、三级告警打断（D3）、一条预警一个处置空间（D4）、**全覆盖控制 + 分级授权**（D5）、先修读视图回填（D6）。
- **控制权限的边界**：**指令即执行**——在操作者角色权限内，工作人员让助手做什么，助手就做什么；助手只负责识别对象、校验参数、预览影响、调用既有服务、回报结果。**助手不放大任何人的权限**：本来能做的，一句话就能做；本来不能做的，助手也不替你做。
- **四期交付**：P0 地基 → P1 抽屉与问答 → P2 主动告警与控制 → P3 协同处置。P0 不做完，P1 之后的验收都不成立。
- **最大风险**：`store` 读视图启动不回填。不修，重启后问"现在有什么预警"会答"没有"——**假阴性比不答更危险**。

## 1. 项目现状与代码链路

### 1.1 助手在架构里的坐标

| 层 | 职责 | 与助手的关系 |
| --- | --- | --- |
| L5 应用层 | `/assistant` 页、全站悬浮图标、抽屉壳 | 交互面。当前对话只在页面里，抽屉是空壳 |
| L4 服务层 | `services/interpret/assistant.py`：意图、白名单、确认闸、叙述 | 助手的全部业务逻辑都在这里 |
| L3 智能体层 | 五段链路的本体（感知/研判/决策/执行/反馈） | 助手**不参与**链路编排，只读链路结果 |
| 总线 | `platform.alert.>`、`ops.feedback.status` | 告警事件的来源，已被后端 SSE 订阅 |
| 存储 | `store` 读视图（进程内）+ PostgreSQL 写侧 | 助手回答的事实来源，**读视图不回填**是当前最大缺陷 |

**架构铁律**（沿用现有约束，不因本次升级放宽）：

1. LLM 只有规划权，不持有执行权（`assistant.py:503-543`）。
2. 执行类动作必须人工确认（`assistant.py:364-395`）。
3. 数字只来自平台真值，LLM 润色引入新数字整段弃用（`text_guard.py`）。
4. 助手读侧与大屏同源（`container.py:764-768`）。
5. 助手不直接调用触达发送接口，告警发送归 `services/response/delivery.py` 与总线。

## 2. 目标与非目标

### 2.1 定位

**值班台的第二块屏**：不替代业务页面，而是在任何页面上都能被叫出来；不替代告警系统，而是告警的呈现、确认与协同入口。

### 2.2 三个时刻（验收场景）

1. **交接班与盯屏**：一句话问出当前生效预警、定级理由、本班未回执任务；答案带来源，能点回原文。
2. **突发**：预警进总线后 2 秒内到达前端；按等级打断；要一个"接手/转派/稍后"；没人确认就升级。
3. **处置**：一条预警一个空间；参与人、任务、回执、共享问答都在里面；换班不丢。

### 2.3 非目标（明确不做）

- 不做开放域闲聊；助手只答平台内事实。
- 不做跨平台 IM（短信/企微触达沿用现有 `delivery`，不在本期 UI 内做）。
- 不让助手直接发布预警、执行处置、改阈值。
- 不做多租户；不做移动端原生。
- 语音输入列为 P4 可选，不作为本期验收项。

| 编号 | 决策 | 结论 | 理由 | 代价 |
| --- | --- | --- | --- | --- |

| D4 | 协同粒度 | **一条预警 = 一个处置空间**（`space_id = warning_id`）；班次视图只做聚合，不做权限边界 | 与现有 `warning_id`、`review/pending` 天然对齐 | 跨预警的"大事件"需要后续聚合 |
| D5 | 助手权限 | **指令即执行**（细则见 §3.1）：在操作者角色权限内，工作人员让助手做什么，助手就做什么——识别对象、校验参数、预览影响、调用既有服务、回报结果、写入审计。**助手不放大任何人的权限**，也不额外设审批环节；仅四类不可逆动作保留操作者本人的一次确认 | 用户要的是"能控制平台"的能力，不是"模型自主决策"；把边界放在角色上，助手只降低操作成本 | 需要全量动作目录、统一执行器、影响预览与回执；权限判定以服务端为准 |
| D6 | 数据真值 | **先修读视图回填**：启动加载最近 N 条 warnings/chains/tasks，写穿时同步；超出 N 条走库查询 | 不修则问答在重启后系统性假阴性 | 内存边界与冷启动时间需实测 |

### 3.1 能力边界与执行规则（D5 的落地口径）

**一句话原则**：助手是"文字版的操作台"，不是"另一个有权限的账号"。它能做的事 = 当前操作者角色能做的事，一项不多、一项不少。

**角色能力矩阵（助手照此执行，不额外设审批）**

| 能力域 | 典型指令 | `duty` 值班员 | `lead` 值班长 | `admin` 管理员 |
| --- | --- | --- | --- | --- |
| 读 | "现在什么情况""这条为什么定Ⅱ级" | ✓ | ✓ | ✓ |
| 上报/演练 | "上报一条""启动一次演练" | ✓ | ✓ | ✓ |
| 任务 | "认领""回执""派给老李""移交给小张" | 认领/回执自己的 ✓；派单 ✗ | ✓ | ✓ |
| 预警 | "发布""撤回""改级""静默""重发" | ✗（提示需值班长，可一键转交） | ✓ | ✓ |
| 规则/阈值 | "确认这条阈值建议""把阈值改成 40" | ✗ | 确认建议 ✓；改规则 ✗ | ✓ |
| 设备 | "打开/关闭某设备" | ✗ | ✓（白名单内） | ✓ |
| 批量/全局 | "把这三条都发出去""全区静默" | ✗ | ✓（二次确认） | ✓ |
| 配置面 | "切到 real 运行时" | ✗ | ✗ | ✗（不开放给助手） |

**三条执行规则**

1. **指令即执行**：有权限的操作者说出指令，助手直接执行，**不再要求"另一个人批准"**；审计记录操作者、指令原文、解析后的结构化参数、执行结果。
2. **无权限就明说**：助手不降级、不猜测、不替人越权；返回"该操作需要值班长权限"，并给出"转交给值班长 / 发起申请"的按钮。
3. **不可逆动作只多一次确认**：发布预警、批量操作、改规则、设备控制四类，执行前展示影响预览（对象、受众、通道、不可逆项），操作者再点一次即可。这是**操作者本人的确认**，不是审批链；高安全部署可把"双人复核"作为配置项打开，默认关闭。

**指令形态**

| 形态 | 示例 | 助手行为 |
| --- | --- | --- |
| 单步 | "把通麦镇这条发出去" | 解析对象 → 影响预览 → 执行 → 回执 |
| 多步 | "先核签，再发布，然后通知下游" | 生成步骤清单 → 逐步执行 → 每步回执；中途失败停在原地并说明 |
| 批量 | "这三条都派给一组" | 列出对象 → 一次确认 → 逐条执行 → 汇总结果 |
| 指代 | "刚才那条撤回" | 从会话上下文解析；歧义时只反问一次 |
| 撤销 | "撤回刚才的发布" | 60s 内直接撤回；超时走正式撤回并提示影响 |
| 能力发现 | "你能做什么" | 按当前角色列出可用动作，不可用的置灰并说明缺什么权限 |

**三条硬边界（不是限制能力，是保证可控）**

- **配置面不开放**：运行时切换、集成开关、令牌、模型配置不属于业务操作，助手不碰。
- **演练与真实隔离**：演练指令只影响演练态，不产生真实触达。
- **服务端校验不绕过**：所有动作最终以操作者身份调用既有服务，前端的置灰只是提示，真正的权限判定在服务端。

**为什么是"人下指令、助手执行"**

- **提示词注入**：上报原文、案例、预警正文都是不可信输入，模型不能自己决定执行；指令必须来自人。
- **责任主体**：指令是人下的，责任在人；助手把指令原文与执行结果一起留痕，审计才追得到。
- **既有铁律**：LLM 只有规划权（`assistant.py:503-543`）、执行段归平台（`agents/factory.py`）；助手是执行代理，不是决策者。

> 结论：**助手不放大权限，只降低操作成本**。工作人员的权限边界不变，但从"翻三层菜单"变成"说一句话"。

## 6. 交互规格

### 6.1 抽屉三段式（从上到下）

1. **告警区**：有未确认告警时置顶，最多 3 张卡，超出折叠为"还有 N 条"。
2. **对话区**：消息流 + 快捷问句 chips（当前预警 / 本班任务 / 区域实况 / 调一张图）。
3. **处置区**：仅在有 `space_id` 时出现，显示参与人、任务进度、未回执数。

### 6.2 告警卡字段（顺序固定）

`等级 · 灾种` ｜ `区域` ｜ `时间` ｜ `影响范围` ｜ `建议动作` ｜ `来源` ｜ `演练标识`
按钮：`接手处置`、`转派`、`稍后提醒`。**不提供"忽略"**——忽略必须走静默并留痕。

### 6.3 状态与空态

| 状态 | 文案与行为 |
| --- | --- |
| 未配 LLM | "规则模式：只能回答白名单内的问题"（沿用现有 `llm_configured`） |
| 无数据 | "当前没有生效预警" + 数据时间戳；不写"一切正常" |
| 腿断 | 指名哪条腿断（如"预警读视图不可用"），不给笼统错误 |
| 断流 | 顶部条"事件流已中断，正在重连"，恢复后补发 |

### 6.4 键鼠

`Ctrl+/` 开合；`Esc` 关闭；`↑/↓` 在告警卡间移动；`Enter` 发送；`Shift+Enter` 换行。

### 6.5 指令直达示例（验收用）

| 工作人员说 | 助手做什么 | 屏幕上出现什么 |
| --- | --- | --- |
| "把通麦镇这条发出去" | 解析到 `wrn_8f2c` → 校验 `lead` 权限 → 影响预览 | 一张卡：对象/等级/受众 3 个村/通道 2 条/不可逆提示 + [确认发布]；确认后回执 |
| "派给老李" | 从席位表解析"老李" → 校验派单权限 → 写 `handling_tasks.assignee` | 回执：已派给李××（值班员），任务 `stu_…` |
| "先核签，再发布，然后通知下游" | 生成 3 步清单 → 逐步执行 | 步骤条 1/3 完成 → 2/3 → 3/3；每步带结果 |
| "这三条都派给一组" | 列出 3 个对象 → 一次确认 → 逐条执行 | 汇总：成功 3 / 失败 0，可展开逐条 |
| "刚才那条撤回" | 解析上下文 → 60s 内直接撤回 | 回执：已撤回，审计已记录 |
| "你能做什么" | 按角色返回动作清单 | 分组的动作面板，不可用项置灰并说明缺什么权限 |

## 9. 风险与开放问题

1. **读视图回填的边界**：只回填最近 N 条，历史仍走库。N 需按内存与冷启动实测定，不能拍脑袋写 1000。
2. **席位声明不是强认证**：正式部署前必须升级为账号或按人令牌；在此之前审计里一律标 `identity_kind=declared`。
3. **告警疲劳**：分级、去重、静默三者缺一不可；上线后先跑一周演练数据看误报率。
4. **LLM 成本与延迟**：规则优先，LLM 只做意图选择与措辞；开放域问答不在本期。
5. **演练与真实混**：事件、卡片、审计三处都要有 `drill` 标识，缺一处就可能把演练当真警。
6. **契约旁路的复杂度**：人走 REST 会让"智能体感知人的动作"延迟一个轮询周期；这是本期接受的取舍。
7. **大权限放大注入风险**：FR-6.10 的围栏与身份隔离必须**先于任何 L3 动作上线**；否则一条恶意上报文本就可能借助手发布预警。
8. **指令歧义与误操作**：指代不清必须反问一次，不能猜；不可逆动作靠"影响预览 + 二次确认 + 撤销窗口 + 限流"四件套兜底。
9. **审计膨胀**：`audit_ops` 与 `control_actions` 会快速长大，P3 起需按月分区并定保留期；审计只追加不等于永久热存。
