### 1.2 组织模式声明（论文 §2.2 对齐）

采用论文 §2.2 的**分层式多智能体协同**：平台编排层（网关+DAG）为中心协调节点，
五智能体经总线点对点收发（`agent.<type>.in/out`），推演沙盒内是 ephemeral 角色智能体
（不注册总线、不计联动成功率、生命周期随推演任务）。这一段直接可写进论文的系统设计章。

### 1.3 一次泥石流事件的端到端数据流（目标态）

```
雨量站 → data.rain_gauge.rainfall_10min
  ① perceive：快腿(EWMA/时空聚集越限,毫秒) ∥ 语义腿(LLM文本/图像线索)
       → perceive.anomaly + perceive.trigger_hit(evidence_refs 溯源到读数)
  ② 平台编排：assess.hazard request(region/window/candidates, deadline_ms)
  ③ assess：MCP工具取 检索佐证+案例+图谱+共享记忆 → LLM 结构化定级
       → 红/橙级：并行第二评估(异模型) → 分歧则仲裁 → assess.risk_level
         (rationale+evidence_refs+model_info+confidence)
  ④ plan：案例检索 → LLM 拆解 STU → stu.v1 校验 → plan.stu_result
       （plan.reschedule 走规则模板 ≤10s，LLM 只做离线优化，不进热路径）
  ⑤ execute：按受众画像三分支文案(领导/救援队/民众) + 藏汉双语
       → 数字必须来自 content_refs 事实，幻觉数字整段弃用 → execute.ack
  ⑥ feedback：回执+响应态汇总 → LLM 归因 → 阈值修正**建议**
       → 人工确认 → calibration 落地 + memory.write(教训入库)
  ⑦ （演练/预案对比时）situation_simulate 节点 → 推演沙盒：
       角色智能体×K情景×T轮 → 概率矩阵+对比报告
全程：trace_id 贯穿；每步 mode=agent/local 留痕；评估样本自动落库
```

### 2.1 D1 详解：哲学修订的准确表述

旧哲学把"安全"理解为"LLM 不碰关键路径"。这在"智能体=外部确定性服务"的前提下自洽；
但 MA-RIAEW 的前提是"智能体=LLM 驱动"，旧哲学执行到底的结果就是智能体层空转
（现状：五段全部降级轨）。新哲学把安全条件从"位置"（在不在关键路径）改为"性质"：

1. **可降级**：每个 LLM 环节都有确定性降级出口（规则引擎/模板），deadline 到即走出口；
2. **可审计**：每次 LLM 调用落 trace（模型、prompt 版本、token、时延、结果 schema 校验态）；
3. **可解释**：所有结论类输出 `rationale + evidence_refs` 必填，进认知镜像；
4. **限时**：LLM 环节只放进预算宽松的段（assess/execute/feedback），≤10s 重调度段禁入；
5. **有栅栏**：动作仍走白名单/人工确认闸；数字防幻觉闸；1–5 级枚举冻结。

这五条全部已有工程承载（降级轨、OTel、认知镜像、deadline、白名单），所以 D1 是
"理由重写 + 能力位补齐"，不是推倒重来。ADR-0002 机制保留、理由修订，记 ADR-0007。

## 3. 五智能体方案（修订版）

### 3.0 公共底座

- **agentkit**（自研契约壳，约 400 行）：AgentMessage/STU 镜像（以 `contracts/*.schema.json`
  为唯一真源）、register/心跳/幂等/deadline/error.raise（规范 §1/§2/§5/§6 客户端）、
  MCP client、LLM client（经网关 v2）。不 import `aegis.*`。
- **框架策略（修订）**：平台本身就是框架——总线即通信层、MCP 即工具层、记忆服务即
  记忆模块、DAG 即编排层。外部智能体框架（AgentScope 等）只在**内环**候选：
  MA 阶段一律无框架薄基线（ReAct 循环 + 结构化输出手写，每智能体约 +250 行）；
  MB 阶段 assess/plan/execute 内环复杂度上来后评估 AgentScope（Apache-2.0，待核对）
  或 LangGraph（MIT，待核对）重构，perceive/feedback 永远保持薄基线。
  选型对照实验（基线 vs 框架的时延/依赖面/门禁通过率）本身是论文素材。
- **模型路由初值**（网关 v2 配置，全部未实测，联调后回填）：

| 用途 | 模型 | 理由 |
| --- | --- | --- |
| assess 定级/仲裁 | qwen-plus（仲裁备选 qwen-max） | 结构化输出稳定性优先 |
| perceive 语义腿 / feedback 归因 | qwen-turbo | 高频低难度，成本敏感 |
| plan 拆解 / execute 文案 | qwen-plus | 生成质量优先 |

| 推演沙盒角色 | qwen-turbo（大量短轮次） | 成本控制 |

### 3.2 assess 研判智能体

| 项 | 方案 |
| --- | --- |
| 契约动作 | 入：`assess.hazard`；出：`assess.risk_level`（1–5 冻结 + confidence + rationale + evidence_refs + `model_info`/`disagreement` 可选新字段，D10） |

| 契约动作 | 出：`feedback.status`（reach_stats/response_state/effect_score） |
| 内环 | 汇总通道回执 + 响应态 + 现场上报 → LLM 归因（哪类受众未触达、响应迟滞环节、效果评分依据）→ **阈值修正建议/传播纠偏建议**（只进建议，落地走人工确认 → calibration 复用） |
| 记忆交互 | 写：`memory.write` 效果验证教训（"X 沟道蓝色预警后 2h 泥位回落"级事实）——群体认知对齐的实体载体 |
| 验收 | effect_score 口径文档化；修正建议→确认→落地的闭环留痕演示 |

### 3.6 推演沙盒（平台 L4 服务，D6）

论文 §3.2.3/§5.3 任务域 3 的落地，也是"多智能体"最出彩的演示位与专利素材：

- **形态**：`simulation` 服务（DAG 节点 `situation_simulate` 升级实现 + assistant `run.drill` 接入）。
  每次推演生成 ephemeral 角色智能体：指挥员、救援队、受影响群众、监测员 + 致灾要素
  （数值模型：降雨-泥位经验关系等，数字冻结自遥测，LLM 不得发明数字）。
- **循环**：K 个情景（参数抽样：降雨强度×初始工况）× T 轮；每轮环境态数值更新 →
  角色智能体 schema 约束行动 → 汇聚器聚合 → 下一轮。
- **产出**：次生灾害概率矩阵（K 情景统计）、关键时间线、**预案对比**（转移/封路/不行动
  三分支效果对比——论文 §3.2.3"预测不同应急预案措施的实施效果"）、推演报告（L5 可视化）。
- **约束**：成本上限参数（K×T×角色×token 预算，超限自动降 K）；完全异步（演练/规划视野，
  不进任何 SLA 热路径）；数字事实与 LLM 叙述分离渲染。
- **验收**：演示性指标（推演报告生成 + 概率矩阵正确性抽查），非 SLA。

## 4. 平台侧改造清单

### 4.1 LLM 网关 v2（D3，MA 先行，一切 LLM 环节的地基）

现状：`services/llm_gateway.py` 129 行、单模型、4 方法、无用量埋点。升级：

1. **多模型路由**：`Settings` 增 `llm_models: dict[用途, 模型配置]`；按 task key 路由；
2. **结构化输出**：`chat_structured(prompt, schema)` —— qwen `response_format` json 模式
   + Pydantic 校验 + 一次修复重试（格式仍错即报错走降级）（**能力未实测，MA 首周验证**）；
3. **流式**：`chat_stream`（assistant token 帧与 execute 文案进度用，可选）；
4. **可观测**：每次调用 OTel span（genai 语义：模型/prompt版本/token/时延/校验态）+
   Prometheus 计数（按 agent_id × model 维度的成本与时延）；
5. **熔断与降级链**：provider 级熔断（连续失败 N 次切备用模型），整链不可用时调用方
   走既有降级轨——LLM 不可用≠平台不可用；
6. **Prompt 注册表**：`prompts/` 目录按智能体分文件、语义化版本、变更过评测门禁（D8）；
   prompt 版本号随结论写进 `model_info`（D10），保证**结论可复现**（评测与论文的前提）。

### 4.2 MCP 工具层 v1（D4，MB）

论文 §4.3 点名 MCP。把平台只读能力封装为 MCP tools（streamable HTTP，平台网络内）：

| 工具 | 后端（全部复用） | 消费方 |
| --- | --- | --- |
| `telemetry.query` | `GET /api/v1/telemetry` | perceive/assess/沙盒 |
| `retrieval.search` | bge-m3 混合检索（已有端点） | assess/plan |
| `cases.search` | 案例库 | perceive/assess/plan |
| `graph.search` | Graphiti 图谱 | assess（灾害链） |
| `memory.search` / `memory.write` | 记忆服务（§4.3） | 全体 |
| `simulation.run` | 推演沙盒（§4.4） | assess 增强/演练 |

价值：工具即审计面（调用留 trace）、智能体内环与平台解耦、与论文四中心直接对表。
实现：官方 `mcp` Python SDK（许可**待核对**）；MA 阶段智能体先按规范 §4 走 REST
（合规即用），MB 切 MCP，REST 端点保留为兼容面。

### 4.3 记忆服务（D5，MB）

论文 §4.2 记忆模块的落地——不自建新存储，统一门面（`services/memory.py`）：

| 记忆类 | 论文对应 | 承载（复用） |
| --- | --- | --- |
| 工作记忆 | 短期：对话上下文 | 现有会话态（assess 单次调用上下文） |
| 情景记忆 | 场景记忆 | 案例库（Postgres） |
| 语义记忆 | 语义记忆 | pgvector（bge-m3 嵌入） |
| 知识记忆 | 程序/知识 | Graphiti 图谱 |

新增**共享记忆命名空间** `agent_memory`（pgvector 表）：`{agent_id, kind(assessment/
disagreement/lesson), content, embedding, refs, valid_at}`。这是论文"共同的记忆模块、
群体认知对齐"的实体：assess 写研判、feedback 写效果验证教训、assess 下次检索引用——
跨事件、跨智能体的经验闭环。MCP `memory.*` 工具暴露；删除/修正走管理端点（记忆可治理）。

### 4.4 推演沙盒实现要点

见 §3.6。工程落点：`services/simulation.py`（编排）+ `simulation/roles.py`（角色
prompt 模板）+ DAG 节点 `situation_simulate` 换实现（节点契约不变）+ assistant
`run.drill` 出报告链接。数值模型先做 2 个（泥石流降雨-泥位、冰湖溃决流量衰减），
覆盖演示灾种即可，**不做全灾种物理模型**（范围闸）。

### 4.5 评测服务体系（D8+D9，MB）

- **金标集**：`eval/datasets/`（git 管）+ Postgres 标注表；种子 = 论文同款公开集 +
  平台 drill 事件（人工确认后的 trigger/assess 结论即标注）——**数据飞轮**（D9）：
  assistant confirm、human_review、解析修正全部自动进标注池，MC 微调数据从这来；
- **裁判评估**：`eval/judge.py` 复刻论文图 7 的 Prompt 体系（总体 + 字段级双口径），
  裁判模型独立配置（DeepSeek API 或 qwen-max）；
- **回归门禁**：prompt/模型/网关配置变更 → CI 跑金标集 → 四表（触发 F1/定级一致率/
  STU 合法率/文案裁判分）不退步才可合入。复用 parsing_eval 的框架经验；
- **模型卡片**：每智能体 `{模型, 版本, prompt版本, 训练数据集, 评测分数}`——评审
  "智能体是什么模型怎么训的"直接出示。

### 4.6 编排归一（D7，MC，风险受控收尾）

chain.py（M1 固定五段）与 workflow engine（M2 DAG）双路径是当前最大的架构债：
降级逻辑、事务口径、指标代码两处维护。归一步骤：

1. 五段链路固化为工作流模板（templates.py 增"标准五段"模板）；
2. 段逻辑（agent 优先/降级判定/降级留痕）下沉到节点实现（`degrade_to_rule` 等
   节点类型已在注册表）；
3. e2e 对照测试：两路径同输入同输出的 parity harness 全绿后，chain.py 退役；
4. `ChainResult.degradations` 等对外口径不变（API/前端无感）。

时序上放 MC（智能体已稳定、指标已重测完）再动编排，避免与 MA/MB 的变更叠加。

### 4.7 assistant 升级：用户交互中心对齐（MB）

- **意图解构引擎**（R6）：LLM 将模糊指令分解为**白名单动作链**（多步计划，如
  "看看波密有没有风险，有的话准备演练" → `query.warnings` + `explain.warning` +
  `run.drill` 提案）。动作空间仍是 12 个白名单不变；执行类动作仍逐个过人工确认闸；
  LLM 只获得"规划权"，不获得"执行权"——论文意图解构与平台安全哲学的交集取法；
- **认知镜像扩展**：assess 结论的 rationale/evidence_refs/model_info 进预警详情与
  链路解释（`explain.warning` 增强）；降级段如实展示"本段由规则引擎代答"；
- **反馈回路**：用户修正（低置信核签的改判等）→ memory.write + 评测样本（D9）。

### 4.8 安全与治理（贯穿）

1. **服务令牌**：规范 §4 数据 API 令牌鉴权的实现状态**待核对**，MA 前补齐；MCP 工具
   继承同一鉴权面；
2. **提示注入防线**：上报文本/案例文本属外部数据进 prompt——分隔符围栏 + "以下为数据"
   指令 + 工具默认只读 + 输出 schema 校验 + 动作白名单，四层纵深；
3. **成本治理**：网关 v2 按 agent_id 月度预算（超限告警不熔断——熔断只给故障不给钱）；
   粗估：drill 20 事件/天 × ~15k token/事件 ≈ qwen-plus 每日个位数元级（**未实测**）；
4. **审计**：LLM 结论的 model_info + trace 保留期与运行态一致。

### 4.9 前端整合点（挂接现有 UI 计划，不另起炉灶）

## 7. 破除与保留清单（一句话版）

**破除**：LLM 不进关键路径的旧哲学（理由重写，机制保留）；智能体外包假设；
单模型 129 行网关；智能体无记忆；意图=词表；chain/workflow 双编排（MC 收口）；
"评测=散装脚本"。

**保留**：五层+一基座；NATS+AgentMessage v1+7 项门禁；自研 DAG 引擎（ADR-0004）；
降级轨与留痕机制；OTel/指标量测点；检索/案例/图谱/标定/解析评测；前端重设计计划；
七层测试体系。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| LLM 时延抖动 vs deadline | 软超时先于网关判定；超期走降级轨（机制既有）；重调度段禁入 LLM（§3.3 硬约束） |
| 结构化输出不稳定 | schema 强校验 + 一次修复重试 + 失败即降级；首过率进质量四表持续盯 |
| 幻觉/越级 | 枚举冻结 + 数字防幻觉闸 + rationale 必审 + 双盲仲裁（高危）+ 白名单不动 |
| 推演沙盒成本失控 | K×T×角色预算上限参数；超限自动降 K 并如实标注 |
| MCP SDK 成熟度/许可 | MA 不依赖 MCP（REST 先行）；MB 引入前按许可证清单口径实测 |
| 微调数据不足 | MA/MB 完全不依赖微调；飞轮从第一天积累；论文同款公开集打底 |
| 编排归一回归 | parity harness 全绿才拆 chain；放 MC 末段 |
| 双评估模型成本翻倍 | 仅红/橙级触发；deadline 紧时跳过留痕 |
| 框架引入失败 | agentkit 框架无关，内环可回退薄基线；对照实验本身就是结论 |
