# ADR-0005：性能技术栈与并发策略

- 状态：已采纳
- 日期：2026-09-29
- 相关：`backend/pyproject.toml`、`tests/perf/test_performance.py`

## 背景

平台需在单机条件下满足调度响应 ≤2s、共享同步 ≤3s、批量接入与并发预警等性能要求，
同时智能体协同、多区域链路、多通道触达都存在天然并发结构。

## 决策

| 主题 | 选择 | 理由 |
| --- | --- | --- |
| Web 框架 | **FastAPI + uvicorn**（ASGI） | 全异步、Pydantic v2 与契约同构、OpenAPI 自动文档；对比 Flask 的同步模型在并发 I/O 下吞吐受限 |
| JSON | **orjson**（缺失时回退标准库） | 消息编解码是热点路径；吞吐由测试下界守护 |
| 事件循环 | **uvloop**（非 Windows 自动启用） | 更高吞吐；Windows 开发机自动回退标准 loop，不做平台假设 |
| 并发原语 | `asyncio.gather` + 超时 | 多区域链路、多通道触达、多源采集、协同事务并发 |
| 队列组 | NATS 订阅 `queue`（工作池） | 同类智能体多实例负载均衡，单实例故障不影响投递 |
| 计时 | `time.perf_counter` 单调时钟 | 系统时钟回拨不得产生负时延或虚假尖峰 |
| 内存 | 环形有界集合（deque/OrderedDict） | 长跑不涨内存；幂等去重表按容量逐出 |

## 反模式（已在实现中规避）

- 用线程池"模拟并发"：受 GIL 与线程切换限制，且取消语义不可靠。
- 无界队列排队：过载时表现为时延雪崩而非可观测的失败；本平台选择**容量饱和快速失败**，
  由上层降级/重调度显式处理（见 `docs/adr/0002`）。
- 在事件循环里做阻塞 I/O：摄取与链路全部异步；`tests/perf` 有心跳不被阻塞的守卫测试。

## 验证

`tests/perf/test_performance.py` 以"相对基线"断言并发是否真实生效
（例如队列组 8 个任务 4 消费者的耗时必须 < 串行基线的一半），绝对阈值给足 CI 余量，避免抖动红灯。
