# ADR-0002：智能体优先、平台降级的双轨链路

- 状态：已采纳
- 日期：2026-09-29
- 相关：`pipeline/chain.py`、`services/`

## 背景

课题要求"感知—研判—决策—执行—反馈"全链条闭环，而智能体由外部实现且进度独立。
平台不能因为智能体未就绪而无法演示，也不能因为智能体返工而中断业务。

## 决策

每一段链路采用双轨：

| 段 | 优先路径 | 降级路径（平台侧） |
| --- | --- | --- |
| 感知 | 智能体 `perceive.trigger_hit` | 规则引擎按站点/时间窗判定（始终运行，两路合并去重） |
| 研判 | 智能体 `assess.hazard` | `RiskEngine` 规则定级 |
| 决策 | 智能体 `plan.stu` | `TaskParser` 灾种处置剧本 |
| 执行 | 智能体 `execute.warn` | `DeliveryDispatcher` 多通道并发下发 |
| 反馈 | 智能体 `feedback.status` | 汇总触达回执并广播 `ops.feedback.status` |

降级留痕写入 `ChainResult.degradations`（可归因，不算失败）；只有链路自身不可用才写入 `errors`（判失败）。

## 后果

- 平台可在零智能体条件下完成端到端演示与压测基线；智能体故障时预警不中断（高原现场关键约束）。
- 双轨带来一定实现重复度；由 e2e 测试同时覆盖两条路径，防止降级路径腐化成"僵尸代码"。
- 智能体超时预算必须小于该段 SLA 预算（研判/决策段 ≤2s），否则降级来不及时指标必然失守。
