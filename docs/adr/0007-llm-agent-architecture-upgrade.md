# ADR-0007：LLM 智能体化与 MA-RIAEW 对齐的架构升级

- 状态：**提议**（随《课题6_架构升级方案》评审，通过后转"已采纳"并回填落地事实）
- 日期：2026-10-11
- 相关：《课题6_架构升级方案》全文、ADR-0002（本 ADR 修订其理由、保留其机制）、
  ADR-0004（不受影响，继续有效）、`contracts/AGENT_INTEGRATION_SPEC.v1.md` §9

## 背景

课题理论框架 MA-RIAEW（导师指定）要求系统"本质由大语言模型驱动的多智能体系统构成"
（论文 §4），LLM 承担认知中枢、任务分解（CoT/ToT）、工具调用（Function Calling/MCP）、
长期记忆（向量库）等核心职责；论文 §6 并以微调+量化实验证明小模型可边缘部署。
现状与该框架相反：LLM 被限制在润色/翻译/兜底四用途，五大智能体未交付，链路五段
全部由规则降级轨承载——任务书"多智能体协同联动成功率 ≥90%"量测对象是 mock，
评审无法回答"智能体是什么模型、怎么训的"。

## 决策

1. **哲学修订（D1）**：安全条件从"LLM 不进关键路径"（位置）改为
   "可降级、可审计、可解释、限时、有栅栏"（性质）。ADR-0002 的双轨机制
   （agent 优先/平台降级/留痕）全部保留，仅理由陈述作废。
2. **智能体自建（D2）**：L3 五智能体由平台团队自建（LLM 内环 + agentkit 契约壳），
   外部团队后续交付仍按契约接入。边界三原则与 7 项一致性门禁不变。
3. **平台补四个能力位**：LLM 网关 v2（多模型路由/结构化输出/用量埋点，D3）、
   MCP 工具层（论文 §4.3 点名，D4）、记忆服务含共享记忆命名空间（论文 §4.2，D5）、
   评测服务体系含数据飞轮（论文 §6 范式，D8/D9）。
4. **推演沙盒为平台服务而非总线智能体（D6）**：论文 §3.2.3 的角色扮演推演以
   L4 服务落地（ephemeral 角色智能体、不注册总线），避免破坏 v1 契约的
   五类智能体枚举；经 `situation_simulate` 节点与演练动作暴露。
5. **编排归一（D7）**：M1 五段链路（chain.py）收编为工作流模板，段逻辑下沉节点，
   parity harness 全绿后退役——消灭双编排路径。时序放 MC（智能体稳定后）。
6. **契约小版本（D10）**：response 类消息增可选字段 `model_info`、`disagreement`
   （规范 §9 允许"只增可选字段"），同步一致性测试。
7. **重调度禁入 LLM**：`plan.reschedule` 的 ≤10s 指标只走规则模板；LLM 仅异步离线
   优化。deadline 倒推的硬约束，写入 plan 智能体方案。

## 不决策（明确出界）

ADR-0004（自研 DAG）不重开；NATS/AgentMessage v1 冻结集不破坏；前端 UI 重设计
计划不变（本升级只挂接整合点）；MD 扩展项（语音预警、图像腿、舆情连接器）不在
本期验收范围。

## 后果

- 正面：R1–R11 能力位补齐（对齐论文四中心/五任务域/实验范式）；联动成功率等指标
  转为真实量测；微调/双盲仲裁/推演沙盒/数据飞轮/框架对照构成论文与专利素材。
- 代价与代价控制：LLM 调用成本（预算+按 agent 限额监控）、结构化输出不稳定
  （校验+一次修复+失败降级）、MB 起维护面扩大（MCP/记忆/评测三个新服务）、
  编排归一的回归风险（parity harness 门禁 + 放最后）。
- 验收：见方案 §5 重测口径；所有未实测数字回填 `docs/REPORT.md`，不写 README。
