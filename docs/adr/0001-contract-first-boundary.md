# ADR-0001：契约先行的智能体接入边界

- 状态：已采纳
- 日期：2026-09-29
- 相关：`contracts/AGENT_INTEGRATION_SPEC.v1.md`

## 背景

L3 五大智能体由另一位成员实现，平台侧由本仓库实现。若两侧以"共享代码 + 直连数据库"的方式耦合，
任何一侧改动都会阻塞另一侧，且指标 3（协同成功率、共享同步时延）无法在平台侧独立取证。

## 决策

1. 智能体是消息总线上的**独立服务**：不 import 平台代码、不直连数据库、不感知平台内部实现。
2. 唯一交互载体是 `AgentMessage v1`（JSON Schema + Pydantic 双镜像，由测试强制同构）。
3. 大体积数据经 `refs` 引用，由平台数据 API 取回；载荷上限约束在契约里。
4. 契约置于仓库 `contracts/`，冻结后只增可选字段；破坏性变更走 v2 并行 subject。
5. 平台交付 **Mock 智能体 + 一致性门禁套件**（规范 §7），真实智能体必须过门禁方可接入。

## 后果

- 正面：两线并行、互不阻塞；契约违规由机制（网关拒收 + CI 门禁）而非口头约定拦截；
  指标量测点全部落在平台侧，可按智能体归因。
- 负面：多一层消息序列化开销；跨进程调试需要总线观测工具（已由 trace_id + Prometheus 覆盖）。

## 备选方案

- 共享 Python 库直接调用：开发最快，但耦合双方进度，且无法度量真实协同成本 —— 否决。
- 仅约定 HTTP 接口：缺少流式协同与事务语义，协同成功率无从定义 —— 否决。
