# ADR-0004：工作流引擎自研 DAG + 状态机（M2 实施）

- 状态：待实施（决策已定，代码在 M2 批次落地）
- 日期：2026-09-29
- 相关：《课题6_项目架构设计》§4.2、`contracts/stu.v1.schema.json`

## 背景

指标 2 要求"≥10 类防控任务节点自定义配置、常规调度响应 ≤2s、异常工况识别与重调度 ≤10s"，
并要求可视化拖拽编排与运行中动态改图。当前 M1 的 `HazardResponseChain` 是固定流水线，
其各段与未来的工作流节点一一对应（STU 已带 `sla_seconds / required_capabilities / fallback_policy`）。

## 决策

1. 自研轻量 **DAG + 状态机**引擎：`Workflow(带版本) / WorkflowInstance / NodeInstance / Edge`。
2. 节点类型注册机制（12 类：触发、判断、并行、会签、人工、API、消息、设备控制、延时、异常、数据接入、预警生成）。
3. 调度队列复用 NATS JetStream，就绪节点事件驱动出队，避免轮询。
4. "柔性"体现为三点：模板与实例版本分离；运行中替换参数/插入节点/旁路节点；异常三段处置（重试/转移/升级）。
5. 画布采用 Vue Flow，语义取 BPMN 2.0 子集（网关/任务/事件），不实现完整 BPMN 规范。

## 后果

- 正面：动态重编排是专利与论文的核心命题，自研可控、可插桩（`≤2s`/`≤10s` 埋点直达引擎内部）；
  依赖面小，弱网边缘节点也能跑。
- 代价：需自建调度器与可视化画布，工作量最大；由 e2e 压测（节点数梯度）守住时延预算。

## 备选方案

- Temporal / Camunda：成熟度高，但"运行中改图"与自定义节点配置仍要二次开发，且引入重型依赖，
  与高原边缘自治目标冲突 —— 作为论文对照方案调研，不引入运行时依赖。
